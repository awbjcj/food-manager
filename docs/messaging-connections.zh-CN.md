# 部署级消息连接

部署者在 `/admin/connections` 统一配置 Telegram、Slack 和 WhatsApp。
家庭成员使用已配置的连接，无需提交自己的机器人凭据。安装连接不会自动授予食材数据访问权限；
家庭邀请、成员角色、封禁、额度和语言设置仍然有效。

部署时配置 `PUBLIC_BASE_URL`（公网 HTTPS 地址）、`CONNECTION_ADMIN_TOKEN`
（至少 32 字符的随机管理令牌）和 `CONNECTION_SECRET_KEY`（Fernet 密钥）。
生成命令见 [.env.example](../.env.example)。将密钥保存在部署平台的密钥设置中，并与数据库备份一同妥善保管。
直接更换加密密钥会使已有凭据无法解密；更换管理令牌会使现有管理会话失效。

运行 `uv run python bin/run.py` 后，打开管理页面，用部署者令牌登录。
没有 Telegram 或 LLM 密钥时也可启动配置页面；使用食材功能前仍需配置 LLM 并重启。
未配置环境变量中的 Telegram 机器人时，`ALLOWED_TELEGRAM_USER_ID` 可设为 `0`。

1. 添加提供商凭据及引导账号 ID。
2. 按连接卡片中的说明配置 Slack OAuth 或 WhatsApp webhook。
3. 验证凭据，并从引导账号向机器人发送私聊消息。
4. 刷新状态并启用连接；发送 `start` 开始使用。
5. 发送 `reminders on` 将此私聊设为每日提醒目标。新选择会替换原目标。

Telegram 新连接使用轮询；同一令牌不能由多个进程同时轮询，也不能保留旧 webhook。
原有环境变量配置会导入为 `legacy-telegram`，令牌仍只保存在环境中。
原有 Telegram 命令、小程序和 Stars 付款保持兼容。

Slack 使用工作区应用。配置页面提供 manifest、回调 URL 和安装入口。
私聊可直接发送命令；频道中使用 `/food pantry` 等命令。
家庭所有者可通过 `/food bind` 绑定共享会话，其他成员仍需加入同一家庭。

WhatsApp 使用 Meta 官方 Cloud API，需要符合要求的企业账号、业务电话号码、系统用户令牌、
应用密钥和明确选择的受支持 Graph API 版本。企业资格、权限及模板审批需在 Meta 平台完成。
24 小时客服窗口之外的提醒必须使用已批准的对应语言模板，正文包含一个 `{{1}}` 参数表示即将到期的食材数量；
可以包含静态页脚，不支持页眉或按钮。缺少模板时会跳过发送。用户仍需主动发送 `reminders on` 开启提醒。

关联已有账号时，先在原连接发送 `link`，在新连接发送 `link CODE`，再回原连接发送
`confirm_link CODE`。请在新连接创建家庭之前完成关联。验证码 10 分钟后失效，
已属于其他账号的身份不能自动合并。退出家庭或被移除后，所有关联身份都失去该家庭的访问权限。

管理页面目前为英文；机器人工作流和引导消息支持英文、中文、法文及西班牙文。
小程序登录和 Stars 付款仍依赖环境变量配置的 Telegram 连接。

入站事件先持久化，再处理业务逻辑；出站消息进入持久化队列。
限流和明确的临时故障会有限重试。发送超时、部分发送成功或外部调用期间重启后，
结果可能未知，此时不会自动重试，以免重复付费调用或重复发消息。
提供商接受请求不代表用户设备已收到消息。当前仅支持单进程、单副本部署。

迁移保留旧 Telegram 用户的内部数值 ID，新用户使用独立生成的内部 ID，
不会给 Slack 或 WhatsApp 用户伪造 Telegram ID。历史账单保持不变。
写入新的消息身份或队列数据后，回滚需要同时恢复数据库和旧应用；降级保护会阻止丢弃这些数据。

本次验证使用本地测试和提供商模拟响应，未连接真实 Slack 工作区或 WhatsApp 企业号码。
完整配置步骤、API 契约和恢复说明见 [英文运维指南](messaging-connections.md)。
