# Mini App 操作指南

[English](mini-app.md) | [简体中文](mini-app.zh-CN.md)

从 Telegram 机器人的**打开应用**菜单进入。**厨房**页面通过表单和交互结果卡片提供用户机器人已注册的全部命令功能。首页快捷入口会打开对应的厨房功能，无需输入命令或返回聊天窗口。

| 分类 | 可用操作 | 对应机器人命令 |
| --- | --- | --- |
| 食材库存 | 查看、筛选、上传不超过 10 MB 的 JPEG/PNG 小票、添加食材、确认或取消更正、撤销、标记已吃或已丢弃、移除、推迟提醒、冷藏或冷冻、统计 | `/pantry`、`/list`、`/add`、`/correct`、`/ate`、`/toss`、`/delete`、`/snooze`、`/stats`、照片及食材按钮 |
| 餐食 | 选择食谱、替代方案、调整、评价、收藏、购物清单、确认已烹饪及历史记录 | `/cook`、`/shopping`、`/favorites`、`/history` 及食谱按钮 |
| 计划 | 查看当前计划、生成 3–7 天计划、替换餐食、添加缺少的食材、取消、导出 `.ics` 日历 | `/plan`、`/calendar` 及计划按钮 |
| 偏好 | 饮食偏好、忌口、菜系、烹饪时间、语言、AI 服务商、时区、每日提醒时间 | `/prefs`、`/lang`、`/llm`、`/tz`、`/digest_at` |
| 家庭 | 查看成员、单次或可复用邀请、加入、离开、户主移除成员、关联 Telegram 群组 | `/household`、`/invite`、`/join`、`/leave`、`/remove`、`/bind` |
| 账户与帮助 | 配额、套餐与加购、账单、取消续费、初始化、帮助、自然语言请求 | `/quota`、`/buy`、`/billing`、`/start`、`/help` 及自然语言 |

家庭和计费功能继续遵循现有托管模式限制。共享处理器仍负责户主权限、封禁、配额、服务商可用性和确认规则。关联群组时，需要填写数字格式的 Telegram 群组 ID，机器人必须能访问该群组，当前用户也必须通过 Telegram 群管理员身份验证。运营机器人管理功能仍独立提供。

界面支持英语、中文、法语和西班牙语。动态结果沿用机器人的翻译流程，AI 功能需要与聊天功能相同的服务商配置。Stars 结账打开 Telegram 支付界面；日历导出提供文件，由用户自行导入。

## 运行机制与验证

`GET /api/workspace` 返回当前用户的卡片和进度。`POST /api/workspace/actions` 提交命令、服务端生成的按钮、更正回复或自然语言输入。`POST /api/workspace/photo` 接收有大小限制的图片。所有接口验证 Telegram 签名身份；新用户在建立家庭成员身份前只能初始化或兑换邀请。

工作区在进程内跟踪耗时任务，任务不依赖单个 HTTP 请求的存活；并发提交会被拒绝，工作区内的请求 ID 会去重。按钮引用服务端卡片及其版本，浏览器不能指定回调内容、其他用户身份或更正回复标记。切换家庭会清除旧卡片，后续请求和处理器执行时仍会检查身份及业务权限。

食材、计划、设置和账单状态保存在 SQLite 中。展示卡片和任务保存在当前进程中：连续一小时没有工作区请求后卡片会过期，重启会清除卡片并停止未完成任务。重启后请重新打开对应功能，检查已保存状态，再决定是否重试修改。Telegram 身份过期后需要从 Telegram 重新打开应用。目前沿用单进程部署模型；部署多个 Web 副本前需要引入共享任务及卡片存储。

验证命令及实现入口参见[英文说明](mini-app.md#runtime-and-verification)。集成测试使用真实 SQLite 数据变更和模拟外部服务，覆盖确认与撤销、食谱生成、家庭隔离、过期按钮拒绝、日历导出、上传限制及命令目录完整性。
