# Frozen Storage State & Shelf-Life Refinement (v4.6) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `frozen` an explicit per-item storage state (separate from food category) so frozen food carries an authoritative months-long expiry instead of a 2-day fresh one, via an LLM hint at ingest plus a one-tap `❄️ Freeze` button.

**Architecture:** Add two additive columns to `PantryItem` (`storage`, `frozen_on`) and change the expiry invariant to `expires_on = (frozen_on or purchased_on) + shelf_life_days`. A new pure resolver (`app/frozen_shelf_life.py`) returns a frozen duration from cache → a vendored USDA FoodKeeper table → the existing web-search shelf-life client → a conservative flat default. Ingest marks LLM-flagged frozen buys; a `❄️ Freeze` button marks anything else, recomputing expiry from the freeze day. One-way (no thaw).

**Tech Stack:** Python 3, SQLModel/SQLAlchemy, Alembic, aiogram, pytest, `uv`. Spec: `docs/superpowers/specs/2026-06-08-v4.6-frozen-storage-state-design.md`.

**Decisions locked here (refinements over the spec, all consistent with it):**
- The resolver's conservative-default branch gets its own source value `"frozen_default"` (the spec listed `"frozen_foodkeeper"`/`"frozen_llm"` as examples; the no-LLM/failure path needs a third).
- The **LLM fallback reuses the existing `ShelfLifeSearchClient`** (`app/refine_service.py`) queried as `"frozen <food>"`, rather than a new LLM client — it is already plumbed into `build_dispatcher`.
- A frozen item's `ingest_shelf_life_source` is set to `"cache"`/`"llm"` (keeping the `IngestShelfLifeSource` literal and the `/stats` cache-hit metric valid); the detailed provenance lives in `shelf_life_source`.

```python
"""Resolve a frozen-storage shelf life for a food.

Order: ShelfLifeCache (frozen key) -> vendored USDA FoodKeeper table ->
existing web-search shelf-life client -> conservative flat default.

The FoodKeeper subset is U.S. government work (public domain). Values are
conservative freezer-storage times in days. /correct learns the rest over
time under the frozen cache key.
"""
from __future__ import annotations

from dataclasses import dataclass
from typing import Literal, Optional

from sqlmodel import Session

from app.cache import get_cached, put_cached
from app.refine_service import ShelfLifeSearchClient, resolve_search_days

FROZEN_DEFAULT_DAYS = 90

FrozenSource = Literal["cache", "frozen_foodkeeper", "frozen_llm", "frozen_default"]

# Curated USDA FoodKeeper freezer-storage times, in days. Keyed by normalized
# food name (see app/normalization.normalize). Conservative on purpose.
_FOODKEEPER_FREEZER_DAYS: dict[str, int] = {
    "chicken": 270,
    "chicken breast": 270,
    "turkey": 270,
    "ground beef": 120,
    "beef": 240,
    "steak": 300,
    "pork": 180,
    "pork chops": 180,
    "bacon": 30,
    "sausage": 60,
    "ham": 60,
    "fish": 180,
    "salmon": 90,
    "shrimp": 270,
    "bread": 90,
    "butter": 270,
    "milk": 90,
    "cheese": 180,
    "ice cream": 60,
    "peas": 300,
    "vegetables": 300,
    "berries": 300,
    "fruit": 300,
    "hash browns": 365,
    "pizza": 60,
}


def _frozen_key(normalized_name: str) -> str:
    return f"frozen {normalized_name}"


def lookup_foodkeeper(normalized_name: str) -> Optional[int]:
    return _FOODKEEPER_FREEZER_DAYS.get(normalized_name)


@dataclass(frozen=True)
class FrozenDecision:
    days: int
    source: FrozenSource
    cache_was_hit: bool


async def resolve_frozen_days(
    session: Session,
    *,
    household_id: int,
    normalized_name: str,
    food_name: str,
    search: Optional[ShelfLifeSearchClient] = None,
) -> FrozenDecision:
    key = _frozen_key(normalized_name)

    cached = get_cached(session, household_id, key)
    if cached is not None:
        return FrozenDecision(days=cached.days, source="cache", cache_was_hit=True)

    table_days = lookup_foodkeeper(normalized_name)
    if table_days is not None:
        put_cached(session, household_id, key, days=table_days, category=None,
                   confidence=0.9, source="llm", commit=False)
        return FrozenDecision(days=table_days, source="frozen_foodkeeper",
                              cache_was_hit=False)

    if search is not None:
        try:
            result = await search.lookup_shelf_life(
                name=f"frozen {food_name}", category=None
            )
        except Exception:
            result = None
        days = resolve_search_days(result) if result is not None else None
        if days is not None:
            put_cached(session, household_id, key, days=days, category=None,
                       confidence=result.confidence, source="llm", commit=False)
            return FrozenDecision(days=days, source="frozen_llm", cache_was_hit=False)

    return FrozenDecision(days=FROZEN_DEFAULT_DAYS, source="frozen_default",
                          cache_was_hit=False)
```

    item_id: int,
    today: date,
    search: "Optional[ShelfLifeSearchClient]" = None,

### Frozen storage state (v4.6)

`PantryItem.storage` (`default | frozen`) is a storage axis **orthogonal to
`category`** — `category` is what the food is (meat), `storage` is how it's kept.
Expiry is `(frozen_on or purchased_on) + shelf_life_days`; `frozen_on` is set when

`ShelfLifeSearchClient` web search (queried as `"frozen <food>"`) → a 90-day default.
Freezing is one-way (no thaw). Frozen items are excluded from the post-ingest web-search
refine and, with their long expiries, fall out of the 7-day digest window automatically.
