# v6.0 Phase 2 — Telegram Stars Payments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a household buy the paid tier and quota top-ups in-bot with Telegram Stars, with an append-only ledger that survives redelivered updates.

**Architecture:** A `PaymentProvider` Protocol (mirroring `LLMClient`) with `StarsPaymentProvider` as the only implementation. Money arrives as ordinary Telegram updates through the existing polling loop — no web server. `PaymentEvent.telegram_charge_id` carries a unique index and is the idempotency key: Telegram can redeliver `successful_payment`, and replaying it must be a no-op.

**Tech Stack:** Python 3.12+, uv, aiogram 3.30 (`create_invoice_link`, `refund_star_payment`, `edit_user_star_subscription`, `get_star_transactions`), SQLModel, pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-07-28-v6.0-multi-tenant-commercialization-design.md` §9

**Depends on:** Phase 1 (`2026-07-28-v6.0-phase1-metering.md`) — all 16 tasks complete and merged.

## Global Constraints

- Everything in Phase 1's Global Constraints still applies (session injection, explicit `now`, naive UTC, byte-identical English, `NowProvider = Callable[[str], datetime]`).
- **Stars invoice rules, enforced by validation in `plans.py`:** `currency="XTR"`, exactly one `LabeledPrice`, `provider_token=""`, `subscription_period` exactly `2_592_000` when recurring, subscription price ≤ `10_000` Stars.
- **`answer_pre_checkout_query` must be answered within 10 seconds.** The pre-checkout handler performs only cheap local validation — no LLM calls, no outbound HTTP, no slow queries.
- **`successful_payment` must be idempotent.** Ledger write and entitlement update happen in one transaction, ledger first.
- Handlers wrap service calls in a catch-all `except Exception`, per the project's recorded convention — but the pre-checkout handler's catch-all must still answer `ok=False` rather than fall silent, or the payment times out.

### Audit corrections

- `record_payment()` stages and flushes; it does not commit. Successful payment
  application owns the single transaction containing ledger and entitlement.
- Checkout validation requires `XTR`, exact amount, correct recurrence shape, a
  non-banned payer in the payload household, and a valid recurring expiry.
- Revenue is purchases minus refunds. Refund events use
  `refund:<original_charge_id>`.
- Renewals do not replace the stable original subscription charge id used by
  Telegram subscription management; renewal ids remain ledger events.

"""Payment rail seam.

A Protocol plus one implementation, mirroring how LLMClient/FakeLLMClient work.
Stars is the only rail in v6.0; the Protocol exists so a second one is additive
rather than a rewrite of the quota and entitlement code.

from __future__ import annotations

from dataclasses import dataclass
from typing import Protocol

from app.billing.plans import Sku


@dataclass(frozen=True)
class LedgerRow:
    """One transaction as the rail reports it, for reconciliation."""

    charge_id: str
    stars: int
    payer_telegram_id: int | None


class PaymentProvider(Protocol):
    async def create_checkout(self, *, sku: Sku, household_id: int) -> str:
        """Return a URL the customer opens to pay for ``sku``."""
        ...

    async def refund(self, *, user_id: int, charge_id: str) -> bool: ...

    async def cancel_subscription(self, *, user_id: int, charge_id: str) -> bool: ...

    async def list_transactions(
        self, *, offset: int, limit: int
    ) -> list[LedgerRow]: ...

    async def create_checkout(self, *, sku: Sku, household_id: int) -> str:
        self.checkouts.append((sku.code, household_id))
        return f"https://t.me/invoice/{sku.code}/{household_id}"

    async def refund(self, *, user_id: int, charge_id: str) -> bool:
        self.refunds.append((user_id, charge_id))
        return self.refund_succeeds

    async def cancel_subscription(self, *, user_id: int, charge_id: str) -> bool:
        self.cancellations.append((user_id, charge_id))
        return True

    async def list_transactions(self, *, offset: int, limit: int) -> list[LedgerRow]:
        rows = [
            LedgerRow(charge_id=cid, stars=stars, payer_telegram_id=None)
            for cid, stars in self.transactions
        ]
        return rows[offset : offset + limit]

```python
import json

from aiogram import Bot
from aiogram.types import LabeledPrice


def invoice_payload(sku_code: str, household_id: int) -> str:
    """Bot-specified payload carried through checkout. Must be 1-128 bytes."""
    return json.dumps({"sku": sku_code, "hh": household_id}, separators=(",", ":"))


def parse_payload(raw: str) -> tuple[str, int]:
    """Inverse of ``invoice_payload``. Raises ValueError on anything malformed."""
    try:
        data = json.loads(raw)
        return str(data["sku"]), int(data["hh"])
    except (json.JSONDecodeError, KeyError, TypeError, ValueError) as exc:
        raise ValueError(f"unparseable invoice payload: {raw!r}") from exc


class StarsPaymentProvider:
    """Telegram Stars implementation of PaymentProvider.

    Payments arrive as ordinary updates through the existing polling loop, so
    no HTTP server, public URL, or webhook verification is introduced.
    """

    def __init__(self, bot: Bot) -> None:
        self._bot = bot

    async def create_checkout(self, *, sku: Sku, household_id: int) -> str:
        return await self._bot.create_invoice_link(
            title=sku.title,
            description=sku.description,
            payload=invoice_payload(sku.code, household_id),
            # Stars: currency must be XTR, provider_token empty, exactly one price.
            currency="XTR",
            provider_token="",
            prices=[LabeledPrice(label=sku.title, amount=sku.stars)],
            subscription_period=sku.subscription_period,
        )

    async def refund(self, *, user_id: int, charge_id: str) -> bool:
        return await self._bot.refund_star_payment(
            user_id=user_id, telegram_payment_charge_id=charge_id
        )

    async def cancel_subscription(self, *, user_id: int, charge_id: str) -> bool:
        return await self._bot.edit_user_star_subscription(
            user_id=user_id, telegram_payment_charge_id=charge_id, is_canceled=True
        )

    async def list_transactions(
        self, *, offset: int, limit: int
    ) -> list[LedgerRow]:
        result = await self._bot.get_star_transactions(offset=offset, limit=limit)
        rows: list[LedgerRow] = []
        for txn in result.transactions:
            source_user = getattr(getattr(txn, "source", None), "user", None)
            rows.append(
                LedgerRow(
                    charge_id=txn.id,
                    stars=txn.amount,
                    payer_telegram_id=getattr(source_user, "id", None),
                )
            )
        return rows
```

"""Append-only payment ledger.

``telegram_charge_id`` carries a unique index and is the idempotency key.
Telegram redelivers updates, so recording a payment twice must be a no-op
rather than a double grant.
"""
from __future__ import annotations

import logging
from datetime import UTC, datetime

from sqlalchemy.exc import IntegrityError
from sqlmodel import Session, select

from app.models import PaymentEvent

log = logging.getLogger(__name__)


def _utc_naive(value: datetime) -> datetime:
    if value.tzinfo is not None:
        value = value.astimezone(UTC).replace(tzinfo=None)
    return value


def find_event(session: Session, *, charge_id: str) -> PaymentEvent | None:
    return session.exec(
        select(PaymentEvent).where(PaymentEvent.telegram_charge_id == charge_id)
    ).first()


def record_payment(
    session: Session,
    *,
    household_id: int,
    charge_id: str,
    kind: str,
    sku: str,
    stars: int,
    payer_telegram_id: int,
    payload_json: str,
    now: datetime,
) -> bool:
    """Append one ledger row.

    Returns True if this is the first time ``charge_id`` has been seen, False
    if it was already recorded - the caller must skip granting on False.
    """
    if find_event(session, charge_id=charge_id) is not None:
        log.info("payment_replay_ignored", extra={"charge_id": charge_id})
        return False

    session.add(
        PaymentEvent(
            household_id=household_id,
            telegram_charge_id=charge_id,
            kind=kind,
            sku=sku,
            stars=stars,
            payer_telegram_id=payer_telegram_id,
            payload_json=payload_json,
            created_at=_utc_naive(now),
        )
    )
    try:
        session.commit()
    except IntegrityError:
        # Lost a race against a concurrent delivery of the same update.
        session.rollback()
        log.info("payment_replay_race_ignored", extra={"charge_id": charge_id})
        return False

    log.info(
        "payment_recorded",
        extra={"charge_id": charge_id, "kind": kind, "sku": sku, "stars": stars},
    )
    return True


def revenue_stars(session: Session, *, since: datetime) -> int:
    """Stars actually taken in since ``since``.

    Refunds and operator grants are excluded: neither is revenue.
    """
    moment = _utc_naive(since)
    events = session.exec(
        select(PaymentEvent).where(PaymentEvent.created_at >= moment)
    ).all()
    return sum(e.stars for e in events if e.kind in ("subscription", "topup"))
```

from app.billing.plans import Sku, limits_for


def apply_subscription(
    session: Session,
    *,
    household_id: int,
    sku: Sku,
    charge_id: str,
    payer_telegram_id: int,
    expires_at: datetime,
    now: datetime,
) -> Subscription:
    """Grant or renew a paid tier.

    ``expires_at`` comes from SuccessfulPayment.subscription_expiration_date and
    is authoritative - deriving it locally would let the bot's period drift from
    Telegram's billing period. Opening a new period naturally starts a fresh
    QuotaUsage row, so no explicit counter reset is needed.
    """
    moment = _utc_naive(now)
    sub = get_or_create_subscription(session, household_id=household_id, now=moment)
    tier = sku.grants_tier or sub.tier

    sub.tier = tier
    sub.status = "active"
    sub.telegram_charge_id = charge_id
    sub.payer_telegram_id = payer_telegram_id
    sub.period_start = moment
    sub.period_end = _utc_naive(expires_at)
    sub.seat_cap = limits_for(tier).seats
    sub.updated_at = moment

    session.add(sub)
    session.commit()
    session.refresh(sub)
    return sub


def apply_topup(
    session: Session, *, household_id: int, sku: Sku, now: datetime
) -> QuotaUsage:
    """Add a top-up's grants to the household's current period.

    Grants live on the QuotaUsage row, so they expire with the period by
    construction - there is no separate expiry job.
    """
    sub = get_or_create_subscription(session, household_id=household_id, now=now)
    sub = roll_period_if_due(session, sub=sub, now=now)
    usage = get_or_create_usage(
        session, household_id=household_id, period_start=sub.period_start
    )
    usage.receipts_granted += sku.grants_receipts
    usage.actions_granted += sku.grants_actions
    usage.cost_micros_granted += sku.grants_cost_micros
    session.add(usage)
    session.commit()
    session.refresh(usage)
    return usage


def apply_refund(
    session: Session, *, household_id: int, now: datetime
) -> Subscription:
    """Downgrade after an operator refund.

    Members already over the free seat cap are not evicted; the cap only blocks
    new joins until the household is back under it.
    """
    moment = _utc_naive(now)
    sub = get_or_create_subscription(session, household_id=household_id, now=moment)
    sub.status = "cancelled"
    sub.seat_cap = limits_for("free").seats
    sub.updated_at = moment
    session.add(sub)
    session.commit()
    session.refresh(sub)
    return sub

async def handle_pre_checkout(query, *, session_factory):
    """Approve or decline a checkout.

    MUST answer within 10 seconds or Telegram fails the payment, so this does
    only cheap local validation - no LLM calls, no outbound HTTP, no slow
    queries. The catch-all still answers ok=False: falling silent is worse
    than declining, because a timeout gives the customer no explanation.
    """
    try:
        sku_code, household_id = parse_payload(query.invoice_payload)
        if sku_for(sku_code) is None:
            raise ValueError(f"unknown sku {sku_code!r}")
        with session_factory() as session:
            if session.get(Household, household_id) is None:
                raise ValueError(f"unknown household {household_id}")
            payer = session.get(User, query.from_user.id)
            if payer is not None and payer.banned:
                raise ValueError("banned payer")
    except Exception as exc:  # noqa: BLE001 - must always answer
        log.warning(
            "pre_checkout_declined",
            extra={"error_class": type(exc).__name__, "reason": str(exc)},
        )
        await query.answer(
            ok=False,
            error_message="This purchase isn't available. Try /buy again.",
        )
        return

    await query.answer(ok=True)
```

```python
async def handle_successful_payment(msg, *, session_factory, now_provider: NowProvider):
    """Apply a completed payment. Must be idempotent - Telegram redelivers.

    Ledger first, then entitlement: record_payment returning False means this
    charge was already applied, so nothing is granted a second time.
    """
    payment = msg.successful_payment
    try:
        sku_code, household_id = parse_payload(payment.invoice_payload)
        sku = sku_for(sku_code)
        if sku is None:
            raise ValueError(f"unknown sku {sku_code!r}")

        now = now_provider("UTC")
        with session_factory() as session:
            fresh = record_payment(
                session,
                household_id=household_id,
                charge_id=payment.telegram_payment_charge_id,
                kind=sku.kind,
                sku=sku.code,
                stars=payment.total_amount,
                payer_telegram_id=msg.from_user.id,
                payload_json=payment.invoice_payload,
                now=now,
            )
            if not fresh:
                return  # already applied; a redelivery, not a new purchase

            if payment.is_recurring:
                expires = datetime.fromtimestamp(
                    payment.subscription_expiration_date, UTC
                )
                apply_subscription(
                    session,
                    household_id=household_id,
                    sku=sku,
                    charge_id=payment.telegram_payment_charge_id,
                    payer_telegram_id=msg.from_user.id,
                    expires_at=expires,
                    now=now,
                )
                key = "payment.thanks_subscription"
            else:
                apply_topup(session, household_id=household_id, sku=sku, now=now)
                key = "payment.thanks_topup"

            payer = session.get(User, msg.from_user.id)
            lang = payer.lang if payer is not None else "en"
    except Exception as exc:  # noqa: BLE001 - a payment must never crash the bot
        log.error(
            "successful_payment_failed",
            extra={"error_class": type(exc).__name__,
                   "charge_id": getattr(payment, "telegram_payment_charge_id", None)},
        )
        return

    await msg.answer(t(key, lang))
```

> a payment that failed to apply.
