# Food Manager v5.1 — Natural-Language Input + Onboarding

**Status:** Design approved (pending spec review)
**Date:** 2026-07-09
**Lineage:** Track 4 of the v5 roadmap (`2026-07-08-v5-roadmap-design.md`); first
release under the roadmap's Agno adoption boundary. Assumes v5.0 (progress acks,
owner alerts) has shipped.

> **Execution refresh — 2026-07-09.** The checked-out repository is pre-v5.0:
> `app/progress.py` and the progress-aware `/add` flow do not exist. This branch
> first lands the small, already-designed v5.0 progress seam required by v5.1;
> unrelated v5.0 alert/watchdog/restart work remains out of scope. The audit also
> tightened action safety: only exact normalized-name matches may auto-apply a
> mark; every partial match opens an item picker. Inventory queries carry an
> explicit `all|digest` scope, DeepSeek uses Agno JSON mode, output is
> semantically validated, and user/pantry text is passed as delimited data.

## 1. Goal

Kill command friction. Today every pantry action needs a slash command with picky
syntax (`/add oat milk 10d`, `/ate 5`), and new household members face a wall-of-text
`/help`. v5.1 makes plain text the default input — "bought milk and two avocados",
"ate the yogurt", "how long does salmon keep?" — and gives newcomers a tiered
`/help` plus a `/start` tour. Slash commands all keep working; natural language is
an additional path, not a replacement.

## 2. Locked decisions (via grilling)

| Decision | Choice | Why |
|---|---|---|
| Intent scope (v1) | **Core actions + Q&A**: add, mark (ate/tossed/snooze/freeze), shelf-life question, pantry query; everything else → help hint | Covers daily friction with a schema small enough to validate. `/cook` stays a command (already one tap). Corrections/shopping-list NL deferred. |
| Confirmation model | **Hybrid** | Adds reuse the existing pending Apply/Cancel cards (LLM adds are already proposals today). Marks apply immediately when exactly one active item matches; ambiguous names get a tappable picker; terminal-action safety comes from exact-match-or-ask, not an extra tap on every action. |
| Agent state | **Stateless** | One message → one parse, with pantry context injected per call. No Agno DB/sessions, no FSM (house style), easy to fake in tests. Pronoun follow-ups are a later nicety. |
| Framework | **Agno** (roadmap boundary) | New agentic seam only; the v4.7 `ProviderSelector` seams are untouched. |

## 3. Intent agent (`app/nl_intent.py`)

The one Agno seam. A Pydantic output schema:

```python
class NLIntent(BaseModel):
    kind: Literal["add", "mark", "shelf_life_question", "pantry_query", "unknown"]
    mark_action: Optional[Literal["ate", "tossed", "snooze", "freeze"]] = None
    item_name: Optional[str] = None   # mark: canonical English item name
    food: Optional[str] = None        # shelf_life_question: canonical English food
    snooze_days: Optional[int] = None # mark/snooze only; validated 1..30
    pantry_view: Optional[Literal["all", "digest"]] = None
```

- **Classify-only.** For `kind="add"` the agent extracts nothing; the handler passes
  the user's raw text to the existing `propose_add`, which owns item parsing and the
  pending-card flow. One LLM owns each job.
- **Per-provider agents, built once at bootstrap.** One Agno `Agent` per configured
  provider (anthropic / openai / gemini / deepseek — all text-capable), using
  `output_schema=NLIntent`. Selected by `User.llm_provider` through a thin selector
  mirroring the text seams: **no fallback** — the user's provider choice is honored
  (text-seam convention from v4.7). Agents are never constructed per message.
- Agent rules use Agno `instructions`; DeepSeek enables `use_json_mode=True`.
  Structured output is validated again at the wrapper boundary, including
  kind-specific required fields and snooze-day bounds.
- **Context per call:** today's date and the household's active item names (capped,
  e.g. 100) so "the yogurt" grounds against real items; the prompt states that input
  may be en/zh/fr/es and that `item_name`/`food` must be returned as canonical
  English (the DB's canonical-EN convention — matching happens on
  `normalized_name`).
- **Cost/latency:** one structured parse per free-text message; acceptable at
  household scale. The v5.0 progress ack covers perceived latency.

## 4. Catch-all handler (`app/bot.py`)

Registered **after** all command handlers and the existing correct-reply handler;
filter = text message, not a command, not a reply. Flow: `_request` auth →
`start_progress` ack → agent parse → dispatch:

| Intent | Dispatch |
|---|---|
| `add` | Raw text → existing `propose_add` → pending Apply/Cancel cards, verbatim (ack cleared, as in v5.0's `/add`). |
| `mark` | Match `item_name` against active items' `normalized_name` (exact, then substring). Exactly one **exact** match → call `mark_eaten` / `mark_tossed` / `snooze_item` / `freeze_item` + localized confirmation reply. Any substring-only match (even one) → picker keyboard reusing `item:open:<id>` so a destructive action is never inferred from a fuzzy name. None → localized "couldn't find *X*" hint. |
| `shelf_life_question` | Answer chain: `ShelfLifeCache` → `shelf_life_defaults` table → the per-user `ShelfLifeSearchClient` if wired (same `_select_search` routing as ingest) → honest "not sure". Never creates items. |
| `pantry_query` | `pantry_view="digest"` reuses `/pantry digest`; `pantry_view="all"` reuses the full `/pantry` view. A shared render helper prevents drift. |
| `unknown` | One-line localized hint pointing at `/help` with an example message. |

**Degradation rule:** any agent exception (provider down, schema violation, agno
bug) logs a warning and falls through to the `unknown` hint — a broken agent must
never break commands or crash the update (the v5.0 error middleware is the
backstop, not the plan).

## 5. Onboarding & tiered /help

- **`/help`** becomes a short overview (what the bot does, the natural-language
  examples, the 3 core commands) plus per-topic detail via `/help <topic>` and
  topic buttons (`help:<topic>` callbacks, edit-in-place via `callback_dispatch`).
  Topics: pantry, cook, household, settings.
- **`/start` without an invite token** sends a welcome tour: one message with what
  the bot does, three example NL messages to try, and `/pantry` · `/cook` · `/help`.
  `/start <invite-token>` keeps its existing join behavior untouched.
- A newcomer who successfully redeems `/start <invite-token>` receives the same
  tour after the join confirmation; invalid/reused tokens do not.
- All copy is new i18n keys (en/zh/fr/es); existing English strings byte-identical;
  placeholder-parity integrity test must pass.

## 6. Wiring & dependencies

- `pyproject.toml`: add pinned `agno`; per the claude-api/provider conventions the
  Agno model classes map anthropic→`Claude`, openai→`OpenAIChat`, gemini→`Gemini`,
  deepseek→OpenAI-compatible with the DeepSeek base URL (verify exact class names
  against Agno docs at plan time).
- `bin/run.py`: build the per-provider agents next to `_build_llm_clients` from the
  same settings/keys; pass the selector into `build_dispatcher` as `intent_agent`.
  If no provider is configured the selector is `None` and the catch-all handler is
  simply not registered (bot behaves exactly as v5.0).

## 7. Testing

House patterns throughout: `FakeIntentAgent` duck-types the agent (canned
`NLIntent` per input) exactly as `FakeLLMClient` fakes the LLM protocol; services
keep injected `session`/`today`.

- Dispatch: each `kind` routes to the right service/render; `add` passes raw text
  to `propose_add` untouched.
- Mark resolution: unique match applies + confirms; multi-match yields the picker
  with correct `item:open:<id>` callbacks; no match yields the hint; matching is
  against English `normalized_name` even for zh/fr/es input (agent output faked
  in English).
- Shelf-life chain order: cache hit short-circuits; defaults next; search client
  called only when wired; "not sure" fallback.
- Degradation: agent raising → unknown-hint reply, no exception escapes.
- Handler registration: commands, replies, and photos still hit their handlers
  (the catch-all must not shadow them); with `intent_agent=None` no catch-all
  exists.
- i18n: new keys complete + placeholder parity; `/help` and `/start` render per
  language.

## 8. Scope boundaries (YAGNI — not in v5.1)

- No conversational memory / pronoun resolution (stateless).
- No NL corrections, shopping-list ops, or `/cook` triggering.
- No voice/audio input (listed in the roadmap's idea pool; separate release).
- No migration, no schema change.
- No change to any existing command's behavior.
